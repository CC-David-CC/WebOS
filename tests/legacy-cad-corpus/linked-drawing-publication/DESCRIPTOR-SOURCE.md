# Bounded registry descriptor repair

The host command registry rejects JSON-stringified parameter descriptions longer than4096 characters. Source inventory through registration capture (handlers never called) measured the original inspect/create/replace/remove descriptions at76/7411/7483/373 characters. The large definition expansion would reject CAD command registration before any Native work.

The repair uses shared `$defs`/`$ref` for reference records and concise conditional field descriptions. The actual shared manager definition/request admission remains unchanged and exact; registry schema metadata is not execution validation. The new inventory is76/3989/4061/373 characters, within the unchanged host cap. Requests still have the unchanged64KiB UTF-8 total, actual128/256/8192/16384 identity limits, strict own-data capture, and semantic/reference validation in PM/Worker. No host/global limit or active index file changed.

This was the explicitly requested descriptor-size calculation, not a test cycle or Native/app success proof. No command handler, test runner, TSC, build, browser, account, service or deployment was executed. Actual complete workflow verification follows composition.
