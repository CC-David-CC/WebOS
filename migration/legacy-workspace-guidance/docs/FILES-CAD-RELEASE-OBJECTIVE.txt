Stage 1 — Dependable Files

Finish one coherent browser-first My files implementation backed by normal server disk files. Evaluate and integrate the existing worker/OPFS research rather than inventing another storage stack.

Required behavior:
- Saved files survive close/reopen and fresh-session recovery.
- Account changes, cancellation, stale windows and concurrent devices cannot silently overwrite another version.
- Conflicts preserve both versions until explicitly resolved.
- Lost replies and possibly committed writes reconcile without blind mutation retries.
- Interrupted downloads publish only complete verified data.
- Temporary files and cleanup cannot remove committed or in-flight data.
- Heavy hashing and processing run in workers with measured concurrency, responsiveness, memory and disk use.
- Changed files transfer changed data where supported; initial or incompatible reads have a safe fallback.
- The Files app provides clear create/open/rename/move/copy/delete/upload/download behavior and truthful sync/error status.
- Temporary Linux files remain separate from My files.

Test signed accounts, independent sessions, concurrent edits, corruption, quota/disk failures, real socket interruption, browser/server crashes and representative files up to 128 MiB. Distinguish process-crash evidence from power-loss guarantees.

Preserve compatibility with existing apps. Keep a documented file/version/session contract for JSketcher and other consumers.
