## Minimal per-window contract

A document window owns a synchronous, observable operation state. Begin a load or local save before the first picker, confirmation, read, serialization, or write await; release it in `finally`, including cancellation, failure, account invalidation and disposal. Reserve the state atomically before dispatch so two calls in the same turn cannot both start. It must cover initial launch loads, retries, Save, Save As, keyboard shortcuts, iframe/native menus, and registered commands that initiate the same save. UI Save controls are genuinely disabled (`disabled` or correct menu accessibility state) while busy and refreshed on each transition; direct command/shortcut invocations independently reject with a clear busy result before snapshot/write. Disabling a button alone is not authority. Never autoqueue another save.

A load or save is owned by the window/document generation and account context. A stale completion must not update another document, controls or dirty state. The save's local durable commit ends the busy period; asynchronous server synchronization and conflict notification are separate and must not keep Save disabled. Preserve an edit revision for the exact captured snapshot: a successful older save cannot mark later edits clean. A conflict, failed/uncertain write or cancellation must not claim success; preserve newer changes and existing recovery behavior. File picker prompts are included only when the operation has actually been initiated; unrelated background stat/sync, and operations in other windows, must not block this window. Separate save/export controls should share the same local-operation ownership if they access or replace that same document; explicit independent output behavior must be defined rather than inferred from names.

A small shared helper may expose `tryBegin(kind)`, an observable `busy`, and an idempotent, generation-bound `finish()` receipt. It must not replace the existing per-app revision, account, expected-version and pending-close protections. Integrations must render from the same state used by command guards, not derive it from network synchronization. This is a proposed contract, not an implemented API.

## Remaining app inventory and coverage

The following system source modules have direct My files read/write and/or snapshot/export paths; source searches found busy-like guards in several, but neither all visible controls nor all alternate save entrances have been qualified: `audio-editor`, `circuitjs`, `data-explorer`, `embroidery-studio`, `excalidraw`, `image-editor`, `replicad`, `stitch-converter`, `svg-editor`. Also inspect their folder selectors, local import, Save As, output/export paths and third-party iframe menus. `microduck` has separate storage-related modules; inspect its actual file ownership and actions rather than treating a filename search in its entrypoint as complete. The above list plus the named table covers the system source modules found by direct `files.write`/`files.importTree` search; helper-mediated or third-party paths require integration review.

`gcode-preview` and `pdf-viewer` are primarily consumers, and engine/library packages such as `ffmpeg`, `gltf-transform`, `onnx-runtime`, `opencascade`, `transformers`, `zip`, and renderer dependencies do not themselves establish an app Save control. Determine any host-exposed export path before excluding them. Other manifest-backed game sources and the unfinished game/app trees must be scanned as they become integrated, including helper-mediated persistence and embedded native menus. There is no blanket claim that they cannot save. A catalog/manifest inventory is necessary but is not a runtime capability test.

## Acceptance tests per integrated app

Hold a real app-owned load after it begins, assert every visible Save/Save As control disabled, and invoke each shortcut/menu/registered Save directly: no snapshot or write begins. Repeat with a held local save, including duplicate same-turn action, cancellation/failure and account/window disposal. Release and verify controls/command recover; verify a separate window remains usable. Save a captured revision while allowing a later edit and assert the later edit stays dirty. Hold server synchronization after local durable completion and verify Save is reenabled. Exercise initial/retry loads and real iframe/native menu paths where present. Use a real account-backed local store for representative integration and explicitly label per-app stubs or native-library limits. Confirm active catalog IDs and actual runtime assets; do not count only tests of the shared helper as app coverage.
