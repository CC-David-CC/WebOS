Stage 1 — Dependable Files

Required behavior:
- Saved files survive close/reopen and fresh-session recovery.
- Account changes, cancellation, stale windows and concurrent devices cannot silently overwrite another version.
- Conflicts preserve both versions until explicitly resolved.
- Lost replies and possibly committed writes reconcile without blind mutation retries.
- Interrupted downloads publish only complete verified data.
- Temporary files and cleanup cannot remove committed or in-flight data.
- Heavy hashing and processing run in workers with measured concurrency, responsiveness, memory and disk use.
- Changed files transfer changed data where supported; initial or incompatible reads have a safe fallback.
- The Files app provides clear create/open/rename/move/copy/delete/upload/download behavior and truthful sync/error status.

Use JSketcher as inspiration and replace coupled implementation where needed.

direction and future extensions. There is no promise that the entire long-term

do not discard them merely to call the work a rewrite.

deadlines, stale-result checks and measured resources.

File-copy clarification — 2026-11-04, explicit user direction

A full detached file copy is acceptable when it releases cleanly once done.
Prove ownership and cleanup on completion, close, cancellation and disposal:
clear retained Blob/array references, revoke owned object URLs, terminate jobs
and release leases. Preserve a copy while its recipient intentionally owns it
and retain authoritative saved data. Browser garbage collection determines when
physical pages are reclaimed; immediate RSS reduction and zero-copy are not
requirements. Remove proven redundant verification/retention, and measure real
lifecycle behavior before expanding memory-related implementation work.
