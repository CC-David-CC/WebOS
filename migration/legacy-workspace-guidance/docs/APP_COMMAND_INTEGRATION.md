# Application commands and new editor integration

An in-page prototype is live for Calculator and Text. Digital Logic has a live, tested adapter; a remote-agent interface and adapters for the remaining apps do not yet exist. The desktop's existing application host, per-window lifecycle and signed-in My files service remain the integration boundary. A command adapter for an app should advertise the operations that app actually supports, accept structured inputs, return structured success or failure, and act only within the invoking user's authorization and selected app instance. Adapters must handle cancellation and window closure, avoid converting arbitrary documents into shell commands, and use file versions/conflict handling already provided by the desktop. Agent invocation requires a separately reviewed transport and authorization; a browser-side API alone does not grant an external agent access. Do not advertise commands that are not implemented and tested.

Candidate work, not yet integrated or live:

- **FreeCAD-Web:** browser WebAssembly port of FreeCAD; assess browser support, asset size, licensing/source distribution, window cleanup and My files bridging before adding it. Preserve its own runtime.
- **Graphite:** browser 2D vector/raster editor; review its document API, third-party connections, source/license and desktop file integration.
- **SolidCraft:** browser parametric CAD with a documented browser command API; its native MCP server is a separate executable and does not automatically connect to browser sessions. The official v0.29.0 web ZIP matched its published SHA-256 (`f7149be2e364505d3a3123db3dd5dff1b37faefd4d9cffd2651f21b1ee3e0cbf`). Against that isolated upstream build, desktop and emulated-phone browser sessions discovered 555 commands, created a 30 × 20 × 10 mm box, measured 6,000 mm³, and verified undo and redo without page errors or observed external requests. This is an upstream API probe, not a CodiServer integration, physical-touch test, source-build verification or broad geometry validation. An additional isolated same-origin probe saved a design through the upstream API and read the resulting OPFS file from a second page in the same browser context. This demonstrates shared origin storage, not an actual cross-account test; the upstream build is unsuitable for direct multi-account embedding without isolation. Its embed mode accepted a synthetic document and allowed a box command without normal persistence, but an isolated test found `file.save_as` returned success and cleared dirty state while no OPFS file appeared. Never expose that save path as an account save; a verified My files bridge and truthful dirty state are required. My files, per-user sessions, multiple windows, command authorization and save/reopen remain to be implemented and tested.
- **OpenZCAD:** browser parametric CAD with command history and B-rep kernel. Assess offline project format and isolate/remove optional provider integrations before connecting My files.
- **OpenGPEX:** browser image editor with WebGPU and plugin commands. LAN fork `box-git:/srv/data/git/OpenGPEX.git` branch `webos-integration` at `cf54c8e6ab2b4f610ba34894a76bed9d92d5c5c7` removes cloud account/storage, update telemetry, feedback and external AI/ComfyUI bridges and routes. A local Chrome smoke run loaded the editor and created a blank image; removed routes returned 404, with no external requests observed in that limited flow. Leave AI provider configuration empty and unsupported until the user supplies an approved backend. GPL source distribution, My files, app lifecycle, shared plugin installation, command authorization, desktop/phone workflows and optional on-device model downloads remain unqualified; the app is not live.
- **OpenGEX:** 3D scene interchange format, distinct from OpenGPEX. Review importer/exporter availability, licensing and mapping to an actual consumer; format support is not yet implemented.

The separate glTF-Transform shared tool supports a narrow browser-safe API (GLB read/write, dedup and weld). It blocks URL fetches and expects apps to supply authorized file bytes. This is not an OpenGEX importer, a standalone editor, a general texture pipeline or an agent interface.

## Calculator prototype

`window.codiDesktopCommands.list()` discovers commands for the active account’s open windows; `execute({windowId, command, args})` invokes one of them. The initial `calculate` command accepts an expression and optional angle unit, updates its calculator window, and returns the result and Ans used. It validates inputs and removes the registration when that window closes. The registry rechecks the account, window and session after asynchronous handlers finish. Local desktop and emulated-phone tests cover two windows, discovery, calculation, invalid inputs, closing and switching accounts; a unit test covers stale async results. This is an in-page JavaScript API only. It is not a remote network endpoint or an authorization boundary against scripts already executing in the same page. It is live in static release `32b1396d37e7cf9ea26976fd4969e87d51dcb8bd6d82c05bb40af358fa753634`; the same desktop and emulated-phone account tests passed against the public site.

## Text prototype

Text adds `inspect` and `replace-range` for the open document. Inspections return bounded UTF-16 slices, document path, length, dirty state and a window-local revision. Edits require the inspected revision and reject stale edits, invalid ranges and split Unicode surrogate pairs. They use the normal editor undo/dirty handling; saving remains a user action through the existing file UI. The revision changes after edits, document replacement and path changes. Local desktop and emulated-phone tests cover inspection, stale edits, Unicode, save, sync, reload and fresh-session reopen. This is live in release `5cfa32d7759cc28449c29a65601572860a054b5ba96950c9a0f4dcc8d78be831`; public desktop and emulated-phone checks also passed. It is not connected to an external agent.

For the SolidCraft probe, obtain the upstream v0.29.0 `solidcraft-web-0.29.0.zip` and `SHA256SUMS.txt` from its official release, verify the listed digest, extract safely, and serve its contained directory on loopback port 19670. Run `node tests/solidcraft-upstream-browser-probe.test.mjs` using the configured local Chrome DevTools endpoint. The archive and extracted runtime are generated/downloaded artifacts and are not committed.

`tests/solidcraft-upstream-storage-probe.test.mjs` checks upstream same-origin storage. `tests/solidcraft-upstream-embed-probe.test.mjs` needs `SOLIDCRAFT_TEST_ROOT` pointing at the disposable served build directory; it creates and removes one synthetic seed file. Neither test touches the live site or a real account.

## Digital Logic prototype

The `truth-table` command simulates the current circuit draft and returns structured columns and rows, plus whether the displayed diagram matches the draft. It uses the existing simulation limits, refuses concurrent file operations and cancels a result if the circuit changes. It does not claim physical hardware validation. Local desktop and emulated-phone account tests cover the full-adder truth table, an edit during calculation, save, sync and reopening in a fresh session. The same desktop and emulated-phone account workflows passed on the public site in release `2f189e6de5c69fedd1acce6f2d1fed70a363ab5d7621ac2eb6239b0a478ce66e`; physical touch and external agent access remain untested.

Text also has a locally tested `save` command. It requires the inspected revision, saves an existing document using the normal version check, and creates an untitled document only at a new My files path. It reports browser-local pending/conflict status, the saved revision, and whether later edits remain dirty; mixed line endings require the normal user confirmation. Local desktop and emulated-phone tests cover stale revision refusal, collision refusal, saving and syncing, closing and reopening. The same public desktop and emulated-phone workflows passed on live release `08032a738c048ed1164eb285192714174364a9425fded8d6d22a133350ccc03e`. Physical touch and external agent access are not verified.

A local and public desktop/emulated-phone test also changes the file in the same browser mirror while Text holds its previous version. A subsequent command save rejects the conflict, preserves the draft and leaves the newer server file intact. A subsequent local and live test used two isolated browser contexts on the same machine: after one session saved while the other was offline, the other command save returned pending and synchronization produced a visible conflict with both versions preserved. Separate physical devices and network faults remain untested.

SolidCraft input bridge investigation: `tests/solidcraft-upstream-memory-open-probe.test.mjs` takes a native design created in an isolated upstream browser context, supplies its bytes through a Puppeteer-intercepted same-origin URL, and verifies the embedded editor measures the expected 6,000 mm³ box. The probe bypasses SolidCraft's own service worker because that worker otherwise handles requests before Puppeteer sees them. This proves a same-origin response can feed the editor, not that an account-scoped service-worker bridge exists or is secure. An actual bridge would need bounded, account-scoped, short-lived access, cleanup, account-switch isolation and testing with the desktop's existing worker. Embedded mode's in-memory save still does not supply document bytes to the desktop and must be solved separately before integration; do not treat its success reply as persistence.

## PDF Viewer prototype

PDF Viewer offers `inspect` for the open document, `read-page` for bounded text extraction and `go-to-page` for visible navigation. The commands are window- and account-scoped, validate arguments, and reject a document change during an asynchronous read. Text extraction is not OCR. Local desktop and emulated-phone account tests cover a three-page PDF, truncation, invalid pages, visible navigation, closing and file sync. The same desktop and emulated-phone account checks passed on live release `c4078f9f3f8c40ee488929da07afd5ab9f5f9568633a362408938b1ce654b03b`. Physical touch, document replacement during a read and external agent access remain unverified.

## Files prototype

Files provides account-scoped `list` and `open` commands. Listing has a bounded page size; opening checks the file exists and has no conflict, then asks the desktop's normal association router to open it. `requested` confirms the request, not that the destination app finished loading. The temporary Linux filesystem is excluded. Local desktop and emulated-phone tests cover listing, pagination, invalid inputs, opening a text file in Text, separate-account isolation and window cleanup. The same public desktop and emulated-phone account workflows passed on live release `d262d34e94746cd068a1d761d6e6426fa6d104b21fb06236e2d02599c89204b2`. Physical touch and external agent access remain unverified.

## Spreadsheet prototype

Spreadsheet provides `inspect`, `read-cell`, and revision-checked `set-cell` commands. Coordinates are zero-based; reads return bounded raw text/formulas, and edits use the normal workbook change tracking. Active cell editing and protected long cells are not overwritten. The revision changes after grid edits, workbook replacement and save to a different path. Local desktop and emulated-phone tests cover formulas, stale edits, a path change, normal save/sync and reopening. Saving still uses the app UI. The same desktop and emulated-phone account workflows passed on live release `f2bbfe34d1235dc96643da491342836d08025931651446752fa54a9c3da343c4`. Dedicated local and public desktop/emulated-phone tests also verified that commands refuse a protected long cell and preserve active uncommitted input. Physical touch and remote agent access remain unverified.

## Replicad prototype

Replicad exposes `inspect` and revision-checked `set-parameters` for its box/cylinder primitive project. It validates the whole model before changing the UI and refuses edits while a parameter field is active. The command changes parameters only; preview and save use the normal controls. Local desktop and emulated-phone tests cover invalid dimensions, stale edits, a 30 × 20 × 10 mm model preview and 6,000 mm³ volume, normal save/sync and fresh-session reopen. The active-parameter guard is implemented but not independently tested. The same public desktop and emulated-phone workflows passed on live release `96542d4bdb665bd55f218ee7293b6f8953c03506ec63d43e4ad872f28c4232b2`. This is not a general CAD API, a manufacturing check or a remote agent endpoint.

## Data Explorer prototype

Data Explorer exposes in-page `inspect`, revision-checked `set-query` and `run-query` commands for the active account's open analysis. SQL uses the existing single-SELECT validation; results update the normal viewer. Local desktop and emulated-phone tests exercised a grouped query, checked the actual result rows, exported CSV to My files and synced it. Commands do not yet return result rows, save analysis or provide external-agent access. Concurrent edits during a query and physical touch remain unverified. The same desktop and emulated-phone account workflow passed on live release `16f73cd88be1b84d88f4d83f9f411925be93bad5abf7f0c8e3fd8e6c84edb067`.
