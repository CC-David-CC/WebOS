# Beta Files assembly candidate

`ops/beta_files_assembly.py` joins the existing managed `Transaction`, `FloorJournal`/`ManagedBinding`, and forward-only `IssuerSwitch` under **one outer host lock**. Nested transactions use the existing `HeldAdapter`; there is no second hosting service or CLI. It performs pre-floor normalization first, then delegates the established order gate → durable floor → issuer installation → v2 route health. Issuer installation retains its journal until the outer journal is cleared and v2 health is verified. Recovery refuses a normalization journal once any floor/issuer transition exists, refuses an issuer journal without the floor, uses gate/forward recovery after the floor, and finalizes a retained issuer record after outer commit. Exact snapshots, root-protected paths and real health/custody/service adapters remain protected-launcher responsibilities.

`tests/beta-files-assembly-test.py` uses actual assembly/floor/binding/transaction/issuer-switch source with disposable filesystem state and seven forked process deaths: after normalization, outer journal, gate, floor, issuer unit write, v2 forward, and outer journal completion. It proves the **fixture's** issuer switch and v2 route do not occur before the durable floor, that pre-floor recovery stays pre-floor, and that post-floor recovery returns to a verified v2 fixture with issuer journal finalized. Its route controller, service state, lock custody, gate health and signed health are fixture substitutes. Separate tests qualify generated Caddy routes, copied webctl + Caddy, signed native issuer continuity and local systemd dependencies, but they have not yet been composed into one real signed-browser/systemd/Caddy acceptance run.

This module has no CLI, installed host binding or authorization to mutate beta. A protected launcher still must bind actual root-owned pinned code and artifacts, exact normalization/gate/v2/reverse snapshots, source/render inventory, real service unit and dependent state, real gate/floor and main-site health, a safe signed file-health mechanism, account/key custody, existing journals, host/source ownership and exact capacity. It must also install/enforce the guarded legacy entrypoints before any floor. The observed `/srv/data` and webhost source ancestry are user-owned, and the current account-volume margin fails the conservative preflight; no proposed leaf can be assumed root-protected. Actual process/systemd/Caddy interruption, root-owned mount setup, upgrade/recovery installer and independent review remain open. No public release is claimed.

The earlier root-only ancestry concern is superseded by the documented trust model: David/root are trusted administrators, while access by untrusted group/ACL writers must be rejected. Likewise, 5 GiB is the required filesystem reserve; 256 MiB is only a proposed, separately reported working margin, and actual required working bytes remain to be measured. The older blanket post-floor legacy-webctl freeze is superseded by the pinned-beta-preserving source candidate in `WEBCTL-FLOOR.md`; pending/unknown transitions still block legacy writes.

`tests/beta-files-assembly-caddy-test.py` additionally runs the same assembled seven-process-death scenarios with a real, separately started loopback Caddy process. It checks the served gate before issuer switching, served candidate after post-floor recovery, and a separate main fixture response during reloads. The route generator, issuer unit/systemd behavior, and main service are still synthetic in this combined fixture; the independently qualified real-generator and local-systemd tests are not yet one end-to-end signed browser acceptance. The fixture uses ports 19998/19999 and stops its Caddy processes.

Normalization recovery now reads its journal with no-follow, bounded regular-file, owner/mode/link-count and stable-fstat checks under the host lock. It requires the exact pinned old/new normalization snapshots and version-1 policy before calling generic Transaction recovery. Both assembled fixtures inject an unpinned normalization journal and verify refusal preserves it and the route bytes. The protected launcher must still verify the parent-directory custody and supply the real pinned snapshots.

The copied-controller normalization/gate regression deliberately imports the pinned baseline `common_live.py` rather than the newly changed OPFS generator. It continues to test the exact old controller path; the distinct candidate generator and 84 exact static routes are exercised by `opfs-generator-test.py` and `opfs-generated-caddy-test.py`. A single real-controller transition between these two generator revisions remains to be qualified in the complete operator fixture.

`tests/opfs-route-controller-test.py` now additionally switches the actual copied managed controller and real local Caddy from the pinned old-generator maintenance gate to the candidate generator's exact 3ad query loader and then back to the gate using a gate-only journal. It verifies the candidate app bytes, directional `opfs_from_gate`/`opfs_to_gate` 14-target inventories, non-beta output and main fixture response, and reverse recovery after an injected post-reload failure. Its floor marker, issuer/services and loopback path/port transformations are fixture substitutes; this does not yet connect the actual `FilesAssembly` to real issuer/systemd and signed browser health. The policy parses exactly one beta hostname block and rejects duplicate or non-beta output drift.

`ops/beta_files_snapshots.py` now builds the actual reviewed baseline, normalized, gate and 3ad candidate hosting snapshots from exact pinned old/new generator bytes, the live baseline manifest, the sealed candidate manifest and the 84-entry route table. It binds every public route to the candidate manifest, rejects drift in all inputs, proves normalization renders identically, and proves candidate generation leaves non-beta production bytes identical. The local test also rejects modified generator/manifest/table inputs. On the observed source pins, initial and normalized Caddy SHA-256 are `bf6b6d67c33640f10f0b023ded8d38e6352ab3d54e10b3f9ee01b225ed9d5031`; a read-only host check matched the initial hash. Gate Caddy is `6a164416d838612c92926b531ed6ab0571f658ea50f916dd2533255a64654392`; candidate Caddy is `95cecea4a8217afaa6e60e7aee28a5ad01fa9158997f0051cb96626f9916fc48`. The future protected launcher must load modules from the same verified bytes, rerun live pins under lock, and separately verify full artifact inventories; these generated hashes do not install or authorize anything.

The ordinary `ManagedBinding` candidate→gate direction after the floor now uses the same version-2 gate-only transaction as emergency gating. Previously it still used version-1 rollback and could transiently restore the candidate during nested recovery. The real local Caddy managed fixture verifies the binding selects gate-only and that an interrupted exact candidate→gate transaction recovers to gate without reloading candidate. The fixture's nested journal preparer recognizes version 2 only for that exact post-floor pair. The real protected launcher still must bind an equivalently pinned preparer and guard generic recovery; an unwrapped version-1 journal remains a documented bypass.

A post-floor outer recovery can encounter a committed ordinary gate→candidate nested journal. The new narrowly pinned `Transaction.recover_old_gate(expected_gate, expected_candidate)` targets the verified **old gate** even when that journal says committed, rather than reloading the candidate before maintenance. A local real-Caddy test creates such a committed journal, rejects an incorrect gate endpoint without changing it, then verifies the bound recovery applies only the gate. Ordinary v1 recovery remains unchanged; the protected launcher must invoke this method only for the exact reviewed post-floor gate→candidate pair, and must still prohibit unwrapped old-baseline recovery.

`ops/beta_files_router.py` now constructs the actual `ManagedWebctlAdapter`, directional `RenderInventory` and held-lock `Transaction` from the exact four snapshot set. Its nested-journal preparation rejects unpinned endpoints and, after the floor, accepts only the exact v1 gate→candidate journal (recovering to the old gate) or the exact v2 candidate→gate journal (recovering to the new gate). The copied-controller/real-Caddy fixture exercises a committed gate→candidate journal through this router, returning directly to gate, and confirms a forged pre-floor inner journal is retained/refused after the floor. Actual launcher-bound callbacks must still enforce real service, signed data, Caddy, backup, custody and capacity checks; the fixture uses redirected services and cannot authorize host installation.

`tests/opfs-assembled-controller-test.py` now composes the real `FilesAssembly`, `FloorJournal`, `FilesRouter`, `ManagedBinding`, `IssuerSwitch`, copied `webctl.caddy_apply`, pinned old/new generators, directional inventories, exact local 3ad assets and a real local Caddy process. Seven isolated child-process exits were tested at normalization completion, outer journal, maintenance gate, durable floor, issuer unit write, v2 route forward and outer completion. Pre-floor cases recover without a floor or issuer change; post-floor cases recover to the exact v2 fixture and finalize the retained issuer journal. The served maintenance gate, candidate app hash and independent main HTTP fixture are checked. Run sequentially with `for stage in normalized journaled gated floor issuer-unit-written forward complete; do CODI_KILL_STAGE="$stage" python3 -B research/beta-isolated-hosting/tests/opfs-assembled-controller-test.py; done` (ports 19847/19848). The fixture substitutes systemd process state, signed health and private custody; despite using real Caddy/copied controller it is not yet the complete real issuer + signed-browser + systemd end-to-end qualification. Its multithreaded fork warning is retained as a fixture limitation.
