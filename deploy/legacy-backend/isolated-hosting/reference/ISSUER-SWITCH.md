# Beta issuer switch candidate

`ops/beta_issuer_switch.py` is a forward-only, **unbound source component**, not an installed operator or authorization to deploy. It derives the candidate issuer unit only from the exact currently observed baseline issuer unit (`e6b8279c…`), changing the native script path to `/srv/data/codi-beta-native/853c12e581c9f89fc3d78507f43941dd16cd0b4b894b28cdb8317e8a58340f21/scripts/serve-connected.py` and adding `--beta-opfs-file-content`. It does not rewrite frontend/gateway units or change their pinned files, private runtime, user files or keys. The release must be installed separately with appropriate root custody and service-user read/traverse permissions before a real plan can be qualified; it is not present at this proposed path.

Under a caller-held existing host lock and caller-verified v2 floor/maintenance gate, this candidate records and fsyncs the exact old/new unit hashes and the three original beta service active states before writing the issuer unit. It daemon-reloads/restarts only the issuer, verifies the exact unit paths/bytes, and starts only frontend/gateway units recorded as originally active if they became inactive/failed. Unexpected states and drift reject; a forward recovery preserves the journal and gated state until all checks pass. Production launcher callbacks must perform **real** floor/gate, root-custody, full native-manifest, same account/key, signed file health and capacity verification. They are not provided by this component. `run_systemctl` names only the supplied command vector; the future protected launcher must pin code and prevent untrusted substitution.

`tests/beta-issuer-switch-test.py` uses actual baseline unit bytes generated by `beta_service_operator.render_units`, disposable files and subprocess kills at five journal/unit/reload/restart/health boundaries. Its simulated systemctl forces both dependents inactive after issuer restart and checks that only the originally-active frontend is restarted while an originally-inactive gateway remains inactive. Unit drift and gate-refusal tests preserve the journal. This tests source/transaction control flow; it is **not** an actual systemd test, actual native process restart, real private-state isolation, signed health, or installed protected launcher. The real issuer/frontend/gateway units have `Requires`/`After` dependencies; their actual systemd behavior and root-owned files require a separate isolated systemd qualification before installation.

`tests/beta-issuer-systemd-fixture-test.py`, when explicitly run as root on a disposable test host, uses unique `/run/systemd/system/codi-opfs-fixture-*` sleep units with real `Requires`/`After`, the actual `systemctl` backend and the issuer-switch control flow. Five process-kill boundaries passed, restoring only the originally active fixture frontend and preserving an originally inactive fixture gateway. The test substitutes unique unit names and fixture unit derivation; it does not access beta unit files or private state. Its cleanup stops/removes only its own units and resets only their failed state. Early fixture runs hit systemd start limits; unique failed states were explicitly cleared and the fixture sets no start limit. This is real local systemd evidence for the bounded control flow, not production service or signed-health qualification.

The assembled operator must follow **gate → fsynced v2 floor → issuer/config switch → originally-active dependent restoration and signed health → v2 route exposure**. No pre-floor issuer switch is authorized by this component.

The issuer journal is now **retained by default** after issuer health succeeds. This preserves the original dependent-unit active-state record if the outer Files route transition crashes after issuer installation; `recover(old, retain=True)` can safely replay while the maintenance gate is established. `finalize(old, outer_journal, check_v2_healthy)` refuses while the outer journal exists (including a symlink), verifies the pinned issuer/dependent units and recorded states, verifies caller-supplied v2 health, then clears the issuer journal under the existing lock. The caller must pin the exact outer journal path and use a real v2/floor/signed-health check. If the outer transition commits and crashes before this cleanup, recovery must detect the remaining issuer journal and finalize it only after verifying the committed v2 state. Fixture tests cover retained replay, refusal while outer work is pending and refusal on failed v2 health. This handshake has not yet been wired into an installed launcher or qualified in the full route/service transaction.
