# Candidate floor-aware legacy webctl

`ops/webctl_floor_candidate.py` is a proposed replacement for the observed copied `webctl_live.py`; it is not installed. It loads mutating commands' operative manifest **after** taking the existing `.controller.lock`. A pending beta Files transition journal blocks legacy writes. After a valid durable v2 floor, ordinary production-mode legacy maintenance can proceed only if the generated beta block and the actual active Caddy beta block both match the pinned 3ad v2 block. The check is repeated before `render`, `save_manifest`, and `caddy_apply`; unrelated site edits that leave beta exact can continue. Prepare/private/raw Caddy rollback are refused while the floor exists. Unknown/malformed floor, unknown beta output or an unexpected active Caddy file refuse mutation rather than guessing. `status` remains read-only.

`tests/webctl-floor-candidate-test.py` invokes the copied CLI's actual dispatch with disposable paths and a real flock. It verifies locked manifest loading, pending-journal and dangling-symlink refusal, a real unrelated `workers` command through dispatch after the floor, and refusal for altered generated/active beta blocks, malformed floor and unsafe modes. The test also verifies that the pinned beta block hash comes from the actual candidate generator. It does not establish the real host invokes this source. A protected installer/launcher must pin and load the guarded code/common, coordinate all other supported beta-mutating entrypoints under the same lock and marker paths, and verify generator/render inventories. Direct unwrapped commands or hand edits by the trusted administrator remain outside this supported-entrypoint contract.

Trust assumption: David/root are trusted administrators; their intentional hosting-source edits are outside this guard. This does not trust other users: ancestry checks must reject untrusted group/ACL writers. A cooperating host lock cannot prevent an uncooperative writer during the check-to-rename window, and a full installation/ACL review and protected forward-recovery launcher remain open. A gate or unknown state may block legacy maintenance until reviewed recovery; refusal does not prove the candidate is inaccessible.
