# Beta Files read-only preflight candidate

`ops/beta_files_preflight.py plan` is a **read-only, plan-only source candidate**. It accepts no apply/recover command. On `box-webhost` as root it opens and holds the existing hosting lock before reading operative unit/source pins, checks root account filesystem headroom without reading account contents, checks three existing beta unit files and active states, requires the guarded legacy controller, and requires exact full-inventory 3ad/853 artifacts under the proposed separate-drive locations with root-owned, non-writable ancestors. Artifact payload hashing streams in 1 MiB pieces. It prints check results and never emits keys or account contents. The 5 GiB plus 256 MiB check is a conservative working-margin precondition, not proof of adequate multi-user or every staging scenario. The plan intentionally reports `ready:false` until a protected complete transition operator, signed health, retained-route checks and old-entrypoint enforcement are actually assembled and installed.

Read-only source was piped over SSH to `sudo -n /usr/bin/python3 -B - plan` on 2026-11-04. The three unit hashes and current site manifest matched and all three beta services were active. It refused readiness because the account filesystem held 5,583,134,720 bytes (< 5 GiB + 256 MiB), guarded webctl was not installed, hosting source ancestry was user-owned, 3ad/853 artifacts were not at the proposed paths, and the complete operator was not installed. `/srv/data` itself is user-owned; a root-owned leaf directly beneath it is insufficient custody, so the proposed path also needs a separately reviewed root-controlled mount/ancestor arrangement. The existing host controller ancestry still has the documented uncooperative-writer race despite the cooperative lock.

`tests/beta-files-preflight-test.py` checks the host boundary, artifact content/inventory, symlink and untrusted path rejection using disposable data; it does not simulate every host check. This plan is not an installed protected entrypoint, does not check real signed file health or perform a route/service transition, and does not make the operator ready to deploy. The plan source must itself be reviewed and loaded from a protected pinned bundle before any eventual host use.

## Trust and budget clarification

The strict root-only ancestry and 5 GiB + 256 MiB hard threshold described in the earlier probe are superseded. David and root are trusted administrators; `protected_ancestors` now accepts their ownership while checking directory modes, group membership and POSIX ACLs for untrusted writers. A disposable test verifies trusted admin ancestry and rejection of world-write and a named untrusted writable ACL. This is a point-in-time check under the cooperative hosting lock, not protection against the trusted administrator deliberately changing source or bypassing the controller. Exact file/manifest hashes and root-owned artifact-file custody remain required.

The required storage floor is 5 GiB. The 256 MiB working margin is a **proposal**, separately reported, not a user-imposed limit. The plan reports whether the floor and proposed margin are met and explicitly reports actual working bytes as not yet measured. A fresh locked read-only probe observed 5,582,733,312 bytes available (214,024,192 above the required floor), so the floor passed and the proposed margin did not. Candidate/issuer artifacts and the guarded controller are still absent; a complete protected apply/recover remains unassembled. No ownership or host configuration was changed.

A measured working component is now available: running the exact 853 issuer's `stage()` against a disposable public-only destination copied 445 files, with 119,279,087 apparent / 120,774,656 allocated bytes on a 4096-byte-block ext filesystem. The exact native manifests still matched after this measurement. The preflight reports that observed staging footprint separately from the required 5 GiB floor and optional 256 MiB planning margin. It is not a measurement of total host rollout cost: filesystem differences, orphaned old public stages, transaction backup, concurrent uploads and other work may require more space. The latest locked probe reported 5,582,483,456 available (213,774,336 above reserve); the observed stage alone would fit, but the full working requirement remains unmeasured. No account contents or private keys were read for this measurement.
