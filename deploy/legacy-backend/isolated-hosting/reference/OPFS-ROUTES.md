# Beta Files candidate route proposal

`OPFS-ROUTE-TABLE.json` is the exact GET/HEAD path, query rule, candidate-relative target and SHA-256 table generated from sealed candidate `3ad04c48…`: 82 exact public assets plus the two query-bearing shell loaders. The generator does not expose `config/`, `patches/`, `shell/` aliases, arbitrary Files bundle files or arbitrary OPFS graph files. Unknown paths within the two new namespaces explicitly return 404. Bare shell URLs and other query strings retain the old baseline behavior. All original retained guarded mirror/loader URLs remain configured. The candidate is proposed under `/srv/data/codi-beta-opfs/<manifest>`, separate from the account filesystem; that does not increase the gateway's available reserve.

The generated beta Caddy block was exercised against a verified local copy of the real sealed candidate, both retained old asset pairs, and three isolated backend stubs. All 84 exact GET and HEAD responses matched their recorded hash/target, bare/wrong-query loaders returned baseline bytes, old guarded URLs returned their pinned bytes, unknown/new aliases returned 404, API/config/gateway reached the stubs, and the maintenance gate returned 503 for all v2 paths, old asset pairs and backend routes. The unmodified generated non-beta output compares byte-for-byte, and Caddy validated the full generated configuration. The actual whole-host, authenticated signed-browser, systemd and floor/issuer transaction are not covered by this routing test.

Read-only unauthenticated beta checks on 2026-11-04 observed HTTP 200 for the existing public `apps.json`, old Files `index.mjs`, its `index.mjs.LEGAL.txt` and an individual old Files license asset; `/browser-sources` returned 404. The proposed static routes preserve that existing public-asset behavior and do not introduce or claim an asset-authentication change. The earlier user-facing source/licenses-page requirement is a distinct behavior and remains outside this scoped route candidate.
